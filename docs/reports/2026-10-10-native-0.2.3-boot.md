# Boot 0.2.3 — scénario tranché : mapping partagé, pas substitution

## Verdict matériel observé

La comparaison d'identités tranche. Au boot du
**10 octobre 2026 à 14:02:44 UTC** (16:02:44 local), `Navi48Native` **0.2.3**,
UUID **1E9DDB5A-0841-3DE1-9999-0D854E226E14** (conforme au build déployé,
SHA-256 `61fc8ffc...`), se retire pendant l'acquisition RO, zéro instance,
deux fermetures PCI à **14:02:45 UTC** et **14:02:51 UTC** :

- `Checkpoint=10`, `PlatformObserved=1`, `DMAObserved=0`, `ComputeObserved=0` ;
- `PlatformDecision=19` et `PlatformResult=19`, soit **`InvalidMap`** ;
- `FailedBar=16`, soit **`0x10` = BAR0** ;
- `BAR0Map/MapCheck=3`, soit **`DescriptorMismatch`** ;
- `RereadPresent=1`, **`RereadMatch=1`** : le provider rend toujours le
  descripteur retenu, avant comme pendant le check ;
- **`DeclaredIsReread=0`**, `DescriptorMatch=0` : le mapping déclare un autre
  objet d'origine ;
- `HardwareTouched=0`, `FirmwareLoaded=0`, `GPUInitialized=0`,
  `ComputePassed=0`, `LanesChecked=0`, `LanesWrong=0`.

**C'est donc un mapping partagé qui déclare un autre objet, pas une
substitution du provider.** Le provider est stable ; c'est l'objet mapping
rendu par `descriptor->map()` qui annonce comme descripteur d'origine un objet
différent de celui sur lequel `map()` a été appelé. Les autres propriétés BAR0
restent conformes (adresse `0xFFFFFFCE66200000` alignée, options `0x4001101`,
256 Mio, physique `0x440000000`, tâche noyau). BAR2/BAR5 non atteints.

## Ce que ça implique pour la suite

Le bail IOKit partagé ne permet pas l'observation RO stricte « mappe
l'objet retenu et exige qu'il se déclare lui-même ». Deux voies possibles,
sans rien masquer :

1. **Suivre l'objet déclaré** : adopter le descripteur annoncé par le mapping
   comme objet de référence, puis revalider entièrement (longueur, segment,
   provider, config) contre lui au lieu du retenu. Risque : valider un objet
   qu'on n'a pas choisi ; la revalidation doit donc être totale, pas un simple
   remplacement de pointeur.
2. **Changer de méthode d'acquisition** : obtenir le mapping par un autre
   chemin (par exemple via le provider plutôt que via le descripteur retenu)
   et vérifier si l'objet déclaré correspond alors.

Dans les deux cas, aucune écriture, aucun passage en RW, aucune commande GPU
avant d'avoir un bail strictement validé. La décision sera codée, testée sur
doubles, construite et déployée par remplacement revu — jamais à chaud.
