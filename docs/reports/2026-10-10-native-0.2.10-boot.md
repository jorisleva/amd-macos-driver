## Le shell interactif : canal prouvé, bug de plumbing identifié

Le client userspace (`tools/n48-shell-cli.c`, lecture seule) prouve :

- `IOServiceOpen(type=0)` : **succès** (triple opt-in + post-hardware OK) ;
- sélecteur invalide (99) : `Unsupported` (**routage OK**, `externalMethod`
  bien appelé) ;
- `open(type=1)` : `Unsupported` (garde de type OK) ;
- sélecteur 0 (`Snapshot`) : `NotReady` — **bug identifié, pas un refus** :
  `shellAction` retourne le résultat de `shellGated` mais ne le stocke jamais
  dans `request.result`, que `shellDispatch` retourne tel quel (valeur
  initiale `NotReady`). Le calcul a lieu, son résultat est perdu en route.

Le fix est d'une ligne (`request->result = shellGated(...)` dans
`shellAction`). Il partira en 0.2.11 avec le diagnostic doorbell (file,
adresse, index programmés vs attendus). Aucune écriture, aucune commande n'a
été envoyée via le shell : seules des ouvertures et lectures refusées par le
bug ont eu lieu.
