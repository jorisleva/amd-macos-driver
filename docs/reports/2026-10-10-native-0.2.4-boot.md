## Le nouveau refus : `FailedStage=1`, `PreflightCheck=7`

L'orchestration échoue à son premier contrôle externe : la recherche
d'accélérateurs existants. Le code fait :

1. `serviceMatching("IOAccelerator")` (check 6) — dictionnaire ;
2. `getMatchingServices(matching)` (check 7) — itérateur ;
3. `getNextObject()` (check 8) — refuse si un autre accélérateur existe.

Le boot s'arrête au check 7 : `getMatchingServices()` a retourné null. Sur ce
système sans accélérateur réel, **l'absence d'itérateur est traitée comme une
erreur, alors que c'est le cas nominal** (rien à exclure). Le garde confond
« impossible d'énumérer » et « aucun concurrent », et refuse dans les deux cas.

Ce n'est pas un problème matériel : c'est notre garde qui est trop strict.
La correction est de distinguer l'échec d'énumération (allocation) de
l'ensemble vide (aucun accélérateur = passage), sans jamais autoriser un
accélérateur existant. Aucune écriture, aucun assouplissement de la propriété
exclusive : un vrai concurrent reste un refus `ExclusiveAccess`.
