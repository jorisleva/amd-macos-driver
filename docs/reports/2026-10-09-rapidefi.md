# Essai Tahoe avec RapidEFI 5.8.0

RapidEFI a été configuré dans son interface Windows en chinois, puis son
export a été adapté et copié sur **D: OPENCORE**. Le prochain choix dans le
menu est **Installer macOS Tahoe (RapidEFI)**, en mode normal.
**L'utilisateur confirme ensuite avoir atteint le menu d'installation.**
Il est affiché en chinois. Ce retour confirme une progression jusqu'à
l'interface de récupération ; l'installation, la stabilité, les périphériques
et l'accélération graphique restent à qualifier. Les nouveaux journaux de
cet essai n'ont pas encore été récupérés.

## Configuration dans l'interface

L'application déjà ouverte indique RapidEFI-Pro **5.8.0**, OpenCore **1.0.8**.
Le relevé automatique retrouve le Ryzen 5600X, la B550M DS3H, la Radeon et
l'Ethernet Realtek. Il signale la RX 9070 XT comme incompatible avec
l'accélération native proposée par l'outil.

L'export automatique a été importé dans **加工EFI**, la page de modification
d'une EFI RapidEFI, avec son fichier `configModel`. Les choix effectués sont :

- Ryzen/Threadripper 17h/19h, **six cœurs physiques**, Tahoe 26, **MacPro7,1**.
- Profil spécifique **B550/A520** et constructeur Gigabyte.
- `SetupVirtualMap=false`, `DummyPowerManagement=true`,
  `ProvideCurrentCpuInfo=true`.
- USBInjectAll et USBToolBox décochés, `ReleaseUsbOwnership=false`,
  `XhciPortLimit=false`.
- WhateverGreen et `agdpmod=pikera` retirés ; aucun argument désactivant
  l'unique GPU d'affichage.
- AMDRyzenCPUPowerManagement et SMCAMDProcessor retirés pour cet essai initial.
- Mode verbeux, `keepsyms=1`, `debug=0x100`, sans `-x` ni valeur fixe de slide.

Les fichiers exportés confirment ces choix. Le
[guide Ryzen de Dortania](https://dortania.github.io/OpenCore-Install-Guide/AMD/zen.html)
documente le traitement B550 et le correctif CPU CPUR.

## Retouches après export

L'export brut comporte cinq erreurs de sérialisation : `HideVerbose` manque
dans chacune de ses entrées `UEFI/Drivers`. Le
[modèle OpenCore 1.0.8](https://github.com/acidanthera/OpenCorePkg/blob/1.0.8/Docs/Sample.plist)
contient ce champ. Il est ajouté dans la version prête à démarrer.

L'export GUI reste conservé intact. Les retouches suivantes sont faites dans
une copie distincte pour garder les choix des essais précédents :

- Identité SMBIOS locale existante conservée, sans publier ses identifiants.
- Audio différé : AppleALC et `alcid=1` retirés ; le codec/layout deviné par
  l'outil n'est pas une qualification audio de cette carte mère.
- EC seul sur le chemin observé `\_SB.PCI0.SBRG`, sans USBX, et table
  `SSDT-CPUR` fournie par RapidEFI. PLUG-ALT, GPRW et son renommage sont retirés
  pour limiter les ajouts ACPI au premier démarrage.
- Variante PAT ancienne limitée à Darwin 17–23 ; la variante algrey pour
  Darwin 24–25 reste active. Les variantes Shaneee restent désactivées.
  Le jeu RapidEFI conserve son patch PCIe spécifique Darwin 25 et les
  quatre remplacements de nombre de cœurs à six. Référence pour les plages
  PAT : [AMD_Vanilla](https://github.com/AMD-OSX/AMD_Vanilla/blob/eaf52ef292abf4ebec899df6d48626569ba50cc6/patches.plist).
- Pilote UEFI supplémentaire `apfs_aligned.efi` retiré ;
  `UEFI/APFS/EnableJumpstart=true` conserve le chargement du pilote APFS
  depuis les conteneurs, décrit dans la
  [configuration OpenCore](https://github.com/acidanthera/OpenCorePkg/blob/1.0.8/Docs/Configuration.tex).
- Composants OpenCore remplacés ensemble par la version **1.0.8 DEBUG** déjà
  vérifiée et en cache ; journaux fichier activés, AppleDebug/ApplePanic actifs.
- Menu manuel, récupération visible, demande GOP 1920 × 1080 sans mode forcé,
  aucune propriété PCI injectée et `NVRAM.WriteFlash=false`.

L'EFI active contient les cinq kexts suivants, issus de l'export RapidEFI :

| Kext | Version déclarée |
| --- | --- |
| Lilu | 1.7.3 |
| VirtualSMC | 1.3.8 |
| RestrictEvents | 1.1.7 |
| AppleMCEReporterDisabler | 1.2, sans exécutable |
| RealtekRTL8111 | 2.4.2 |

Leur ordre respecte les dépendances Lilu. Aucun kext USB, graphique ou pilote
expérimental du projet n'est inclus. Le retrait des plugins ne retire pas les
pilotes intégrés de macOS et n'établit pas la cause du blocage CoreAnalytics.

Les retouches ne sont pas toutes représentées par les cases de RapidEFI.
Un nouvel export GUI doit être contrôlé et adapté avant utilisation : le
`configModel` d'origine ne suffit pas à reproduire les changements manuels,
comme l'explique la
[documentation de RapidEFI](https://github.com/JeoJay127/RapidEFI-Tool/blob/main/docs/%E5%8A%9F%E8%83%BD%E4%BB%8B%E7%BB%8D.md).

## Copie et validation

Le support USB est identifié avant écriture par son type, sa capacité et son
identifiant matériel ; il n'est ni disque système ni disque de démarrage
Windows. Aucune partition n'est formatée. La récupération Apple existante
reste sur le support.

- `ocvalidate` **1.0.8** : aucune erreur sur le profil préparé et sur D:.
- Tables SSDT : signature, longueur et checksum corrects ; EC sans USBX.
- Kexts : fichiers et tranches x86_64 présents, dépendances vérifiées.
- **98 fichiers** actifs identiques par SHA-256 à la préparation.
- **63 fichiers** de l'ancienne EFI identiques à la sauvegarde préalable.
- Libellé de récupération relu ; DMG et chunklist Apple présents.
- Script de restauration complet contrôlé par l'analyseur PowerShell ; il
  n'est pas exécuté afin de conserver le nouvel essai actif.

Les exports privés, manifestes, script de préparation et preuves sont dans
`out/opencore/rapidefi-5.8.0-2026-10-08/`, ignoré par Git. Le dossier conserve
la date de début de la configuration ; la copie finale a lieu le 9 octobre.
L'export GUI est sous `configured-ui/`, le profil adapté sous `ready/`.

## Essai et retour arrière

Redémarrer avec **F12**, choisir le disque USB en **UEFI**, puis
**Installer macOS Tahoe (RapidEFI)**. Garder l'écran sur la Radeon : le 5600X
n'a pas d'iGPU utilisable par les sorties de la carte mère. Utiliser un clavier
filaire et Ethernet. Ne pas lancer Reset NVRAM pour cet essai.

Si le démarrage bloque, conserver la photo des dernières lignes et les nouveaux
`opencore-*.txt`. Les journaux OpenCore ne couvrent pas toutes les étapes du
noyau ; l'absence de nouvelles lignes ne désigne pas à elle seule le composant
responsable. Relever aussi le connecteur vidéo, le port USB et la réaction du
voyant Verr. Maj.

La sauvegarde complète est `D:/PROFILS-TAHOE/avant-rapidefi/EFI/`.
Pour restaurer le profil précédent depuis Windows :

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File D:\PROFILS-TAHOE\restaurer-avant-rapidefi.ps1
```

Cette restauration complète précède l'emploi des anciens scripts de profils
USB/graphiques, qui peuvent ne restaurer qu'une partie des composants.
La lettre du support peut changer sur une autre machine.

## Langue française et récupération du projet sur le Mac

L'export GUI original et sa première copie prête à démarrer contenaient
`NVRAM/Add/7C436110-AB2A-4BBB-A880-FE41995C9F82/prev-lang:kbd = zh-Hans:252`.
Ce réglage chinois avait été conservé par erreur lors de l'adaptation.
Le correctif français utilise les octets ASCII **`fr-FR:1`** ; l'identifiant
**1** est la disposition French dans la
[liste OpenCore 1.0.8](https://github.com/acidanthera/OpenCorePkg/blob/1.0.8/Utilities/AppleKeyboardLayouts/AppleKeyboardLayouts.txt).
Le générateur du dépôt utilise désormais cette valeur. La variable figure
aussi dans `NVRAM/Delete` pour remplacer une valeur préexistante au démarrage,
sans demander un Reset NVRAM global.

Un outil dédié change uniquement cette variable et son entrée Delete,
sauvegarde la configuration précédente et conserve les réglages qui viennent
de permettre l'accès au menu. Exemple après installation, avec Python 3 :

```sh
python3 tools/set-opencore-language.py --config /Volumes/OPENCORE/EFI/OC/config.plist
```

Vérifier le chemin du support monté avant cette commande. Le premier correctif
avait été préparé et validé localement pendant que D: était inaccessible.
Après le retour du support sous Windows, le fichier actif
`D:\EFI\OC\config.plist` contenait toujours `zh-Hans:252`. L'outil a maintenant
appliqué `fr-FR:1` directement sur ce fichier, après vérification du disque USB.

La comparaison des configurations avant et après confirme que seule la langue
a changé ; l'entrée Delete était déjà présente. La relecture de D: et
`ocvalidate` 1.0.8 sont réussies. La configuration précédente est sauvegardée
dans `D:\PROFILS-TAHOE\avant-langue-francaise\config.plist`, avec une copie
locale dans `out/diagnostics/tahoe-language-fr-20261009/`. L'empreinte SHA-256
du fichier actif corrigé est
`48c33ed18b3f09518d817c0ac8697c482be6a0c08b664bcebbf93ccaa59d21f7`.
L'affichage en français au prochain démarrage reste à confirmer.

Le code, les scripts, les shaders et les rapports sont sur la branche
**codex/amd-validation-bootstrap**. Sur un Mac sans copie du dépôt :

```sh
git clone --branch codex/amd-validation-bootstrap https://github.com/jorisleva/amd-macos-driver.git
cd amd-macos-driver
```

Si le dépôt existe déjà sur le Mac et ne comporte pas de changements locaux
qui empêchent le changement de branche :

```sh
git switch codex/amd-validation-bootstrap
git pull --ff-only
```

Les EFI complètes dans `out/`, leurs identifiants SMBIOS privés et les paquets
Apple restent des fichiers locaux. La copie qui a démarré est sur le support
USB ; le générateur du dépôt conserve ses versions épinglées distinctes.
Pour poursuivre le développement, commencer par le README et NEXT-STEPS ;
ne pas reconstruire ou remplacer immédiatement l'EFI qui vient de démarrer.
