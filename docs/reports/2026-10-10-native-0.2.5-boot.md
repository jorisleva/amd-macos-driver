**`PreflightCheck=12` est le premier mapping RW BAR0 de l'orchestration
compute** (`11 + 0*2` = descripteur BAR0, `12 + 0*2` = mapping BAR0). Le
contrôle vérifie descripteur, longueur, tâche noyau, adresse alignée, options
RW/UC, segment physique et base config. L'une de ces propriétés du mapping RW
ne correspond pas — exactement le même type de divergence que le socle RO a
apprise à diagnostiquer champ par champ, mais cette fois dans le chemin
compute RW, qui ne publie encore que le code global.

## Ce que ça implique pour la suite

Le socle RO (adoption + DMA) et le préflight accélérateur passent
désormais. Le verrou suivant est le mapping RW BAR0 de l'orchestration : il
faut y porter le même diagnostic au champ près (descripteur, tâche, longueur,
segment, options, adresse) au lieu du `BadArgument` global. La correction ne
change aucun garde : elle nomme la propriété divergente, puis on décidera si
l'objet déclaré RW se revalide comme en RO, ou si la méthode diffère.
